# Модуль «Задачи»

## Назначение

Простая доска поручений владельца сотрудникам на точке — «подкачать колёса», «протереть стёкла», «сходить в магазин за сдачей». Не полноценный таск-трекер: без приоритетов, сроков, повторов, вложений и истории изменений — три статуса и назначение исполнителей, ничего сверх этого. Модуль отключаемый (`Tenant.tasksEnabled`, Настройки → Система → «Модули»), по умолчанию включён, не привязан к пакету/лимитам (см. `00-architecture.md`, «Модульность»).

## Модель данных

`Task`: `title`, `note` (опционально), `status` — открытая строка (не Prisma enum, тот же приём, что `MoneyOperation.type`), единственный источник допустимых значений — `TASK_STATUSES = ["todo", "doing", "done"]` в `src/lib/tasks.ts`, импортируется и API, и UI, дублирующего списка нигде нет.

Задача привязана к **точке** (`pointId`), не к зоне и не к тенанту целиком (решение 2026-07-09): у владельца с несколькими точками — своя доска на каждую, оператор видит доску только своей точки (он не привязан к точке напрямую — попадает на неё через устройство, с которого вошёл).

Назначение — два независимых списка: `assignedOperators` (операторы) и `assignedUsers` (пользователи-владельцы, на практике — только «назначить самому себе»). Оба списка пустые = «видят все сотрудники точки». Список `assignedUsers` не влияет на то, что видит оператор — это только личная пометка «моё» для владельца, доска владельца и так показывает все задачи точки независимо от назначения.

Нет полей: срока выполнения, приоритета, повторения/расписания, вложений, комментариев/ленты активности, ручной сортировки (список сортируется по `createdAt`). Нет отдельной таблицы истории — единственный «журнал» — производный подсчёт «выполнено за последние 24 часа» по `updatedAt`, не персистентный лог.

## Доступ и права

Тумблер «Задачи» — Настройки → Система → «Модули», как и у остальных отключаемых областей (Инструктажи/Лендинг/Товары/Клиенты). Выключенный модуль пропадает из нижнего бара и из «Ещё» владельца; серверные проверки на всех эндпоинтах (владельческих и операторских) отклоняют запрос отдельно от скрытия в UI — кроме счётчика для бейджа (см. «Навигация» ниже), который при выключенном модуле молча возвращает нули, а не отказывает, чтобы бейдж гас, а не замирал на старом значении.

У оператора нет отдельного тумблера доступа к Задачам (в отличие от Товаров/Билетов) — если модуль включён у тенанта, задачи своей точки видит любой активный оператор, с учётом правила видимости по назначению выше.

## Доска владельца (`/tasks/[pointId]`)

Три вкладки-канбан по статусам — «Надо сделать» / «В процессе» / «Выполнено», с иконками и счётчиком задач на каждой (плоский список без канбана уже пробовали убрать в 2026-07-13 — вернули по фидбеку 2026-07-17: скрывать стадии прогресса не годится). Если у владельца несколько точек — переключатель точки над доской; если одна — просто статичное название.

Карточка задачи в списке: заголовок (зачёркнут и приглушён у выполненных), описание, чипы исполнителей («все сотрудники», если список пуст, иначе — по чипу на оператора цветом его `colorTag`, плюс отдельный чип «Я» для самоназначения владельца — тот же плоский стиль чипов, что у сотрудников зоны, без аватара/иконки в самом списке карточек), кебаб-меню действий.

Кебаб: «Изменить» (открывает форму редактирования), три пункта «Переместить в …» (текущий статус — неактивный пункт), «Удалить задачу» (с подтверждением, необратимо).

Форма создания/редактирования (bottom sheet): «Что нужно сделать» (обязательно), «Описание» (необязательно), «Ответственные» — ряд тоглов-чипов: «Я» + по одному чипу на каждого активного оператора (аватар/иконка/первая буква имени, тонировано цветом сотрудника), подсказка «пусто = видят все сотрудники». Статуса, срока и приоритета в форме нет — статус меняется только через кебаб-меню владельца или кнопку прогресса у оператора.

## Экран оператора

Отдельного раздела «Задачи» в PWA нет — это карточка на главном экране оператора (`/operator`), рядом со счётчиком «N активных»/«всё сделано». Список показывает только задачи своей точки СО статусом, отличным от «Выполнено», отфильтрованные по назначению (список назначенных операторов пуст ИЛИ оператор в этом списке — назначение владельца самому себе на видимость оператора не влияет). Строка задачи: индикатор (закрашенная точка у «в процессе», пустое кольцо у «надо сделать»), заголовок, описание, статус строкой + пометка «· общая», если задача не назначена никому конкретно. Ниже списка — «Выполнено: N» (скользящее окно 24 часа, не календарный день).

Тап по задаче открывает bottom sheet с одной кнопкой: «Взять в работу» (надо сделать → в процессе) или «Выполнено» (в процессе/иначе → выполнено) — оператор двигает статус только на один шаг вперёд за раз, отката назад для оператора нет (только владелец может вернуть задачу кебаб-меню в любой статус). Переключение статуса — атомарная операция с проверкой текущего статуса на сервере (защита от двойного тапа на медленной сети: при гонке второй запрос получает отказ «статус уже изменился, обновите страницу», а не тихо требует лишний тап).

Список оператора обновляется без перезагрузки страницы двумя механизмами: пуш-уведомление о новой задаче триггерит немедленный повторный запрос через service worker, плюс фоновый опрос раз в ~25 секунд как запасной вариант для тех, у кого пуши не разрешены.

## Уведомления и навигация

Единственное пуш-уведомление модуля — при создании задачи владельцем («🗒️ Новая задача», текст — заголовок задачи, ссылка на `/operator`). Получатели — те же, кого задача касается: если назначены конкретные операторы, пуш получают только они; если не назначена никому — все активные операторы, у которых есть доступ к зоне на этой точке (все зоны или явный список, включающий зону этой точки). Уведомлений об изменении статуса, выполнении, удалении или переназначении — нет. Email/сводок для задач тоже нет — это единственный отключаемый модуль в проекте без интеграции со сводками.

Бейдж на пункте «Ещё» нижнего бара (когда «Задачи» сам не попал в бар — см. `03-design-system.md`, «Навигация»): красная точка, если есть хотя бы одна задача «Надо сделать»; иначе зелёная, если есть хоть одна «В процессе»; иначе бейджа нет. Опрашивается при каждой навигации владельца.
